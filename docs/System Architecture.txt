# Why your Evidence Reliability Engine belongs specifically under Web

Your thinking is correct.

The Web Search Agent might return:

```text
Result 1 → NICE guideline
Result 2 → PubMed systematic review
Result 3 → Random medical website
Result 4 → Peer-reviewed study
Result 5 → Case report
```

The Web Agent's job is:

> **Find information.**

It should NOT be responsible for deciding whether every result is trustworthy.

So:

```text
WEB SEARCH
     ↓
Find 20 possible sources
     ↓
EVIDENCE RELIABILITY ENGINE
     ↓
Determine which evidence should be allowed forward
```

This creates a very clean division.

# What exactly happens inside the Evidence Reliability Engine?

Suppose Web Search returns this:

```text
Paper A
Published: 2026
Systematic Review
Peer-reviewed
DOI verified
Supported by other studies

Paper B
Published: 2014
Case report
No DOI
Weak relevance

Paper C
Medical blog
No identifiable scientific publication
```

The reliability engine doesn't simply say:

```text
A = good
B = bad
C = bad
```

Instead, it creates a structured profile.

For example:

```text
             Source
                │
       ┌────────┼──────────┐
       ▼        ▼          ▼
   Authority  Recency   Evidence Type
       │        │          │
       └────────┼──────────┘
                ▼
        Metadata Verification
                │
                ▼
         Claim Verification
                │
                ▼
        Cross-source Agreement
                │
                ▼
            Trust Score
```

# Very important: Trust score ≠ correctness

This is a distinction you should maintain in your research.

Suppose a prestigious journal publishes a paper.

That gives it a higher **source credibility**, but that doesn't guarantee that every statement in the paper is correct for your particular patient.

So you really want two concepts:

### 1. Source Trust

> "How trustworthy is this source?"

### 2. Evidence Relevance/Support

> "Does this evidence actually support this particular claim and patient case?"

Therefore:

```text
Source Trust
      +
Patient Relevance
      +
Claim Support
      +
Recency
      +
Cross-source Agreement
      ↓
Evidence Quality
```

This is much more scientifically defensible.

# Then what is the Evidence Reranker?

This should be **after all three evidence sources come together**.

Suppose you have:

### RAG

```text
5 passages
```

### Knowledge Graph

```text
8 relevant relationships
```

### Web

```text
10 verified sources
```

You now have:

```text
23 pieces of evidence
```

You shouldn't blindly give all 23 to the LLM.

The Evidence Reranker can rank them:

```text
#1 Current clinical guideline
#2 Systematic review
#3 High-relevance RAG passage
#4 Validated research paper
#5 Knowledge graph relationship
...
#20 weak evidence
```

Then only the strongest evidence is passed to the Fusion Agent.

So:

# Reliability Engine = "Is this web evidence trustworthy?"

# Reranker = "Among all available evidence, which evidence is most useful?"

That's a very important separation.

The graph therefore generates a **structured hypothesis space**.

## The core idea of your architecture

Your whole system can be remembered as:

> **Multimodal Agent understands the patient.**
> **RAG finds relevant medical knowledge.**
> **Knowledge Graph finds relationships.**
> **Web Search finds fresh evidence.**
> **Reliability Engine determines how trustworthy the web evidence is.**
> **Reranker selects the strongest evidence from all sources.**
> **Fusion combines everything and detects conflicts.**
> **Confidence Calibration estimates uncertainty.**
> **Adaptive Optimizer investigates when uncertainty is high.**
> **Abstention prevents the system from pretending to know when evidence remains insufficient.**

That is a **very coherent one-year major-project architecture**. It also gives you a natural experimental story: **Does each layer make the clinical reasoning more reliable?**
